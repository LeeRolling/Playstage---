# 内测怎么更新

剧戏台仓库现已**公开**（MIT）。试用的人每次双击 `start.bat`（或运行 `start.sh` / `npm start`）时，程序会先直连 GitHub，看 `main` 上的版本。直连不上时，会自动改用公开镜像再试。镜像只读公开的仓库文件，**不会收到令牌**。有新版本就只换程序文件，然后打开。直连和镜像都不通，或你选择跳过，都会用这台电脑上现有的一份打开，演戏不受影响。

## 版本记在哪

仓库根目录的 `VERSION` 是唯一的版本标记，例如 `0.3.0`。`package.json` 里的版本要和它相同。

要换上去的程序文件列在 `update-manifest.json`。每个文件有一条 SHA-256。这份清单发布在公开仓库的 `main` 上。直连时先核对 GitHub 给出的内容指纹，再按清单核对每一个文件。改走镜像时没有这份指纹，仍按清单的 SHA-256 核对。有任何一个对不上，就**不替换**，继续用现有版本。

## 更新时会留下什么

这些不会被换掉，也不会被删掉：

- 整个 `data/` 文件夹。这里有 `library.json`（存档、人设、智谱和千问的钥匙）、`data/media` 里自己的图、`data/github-token.txt` 里的令牌。
- `assets/` 里清单上没有的文件。自己另放的图会留着。

会换掉的是清单里的程序：页面、规则、启动脚本、说明，以及仓库自带的默认图。不要直接改 `assets/defaults` 里同名的那张图，更新时会换回仓库里的那一份。自己的图请放在 `data/media`，或放一个清单里没有的新文件名。

剧戏台仍然不下载模型。

## 仓库主人：发给试用的人

公开仓库可直接把地址发给对方：`https://github.com/LeeRolling/Playstage---`（Code → Download ZIP，或 `git clone`）。不再需要先加协作者。若仍用旧的只读令牌流程，也可以继续放在 `data/github-token.txt`。

发一个新的内测版本时，先在剧戏台文件夹里双击 `check.bat`（Mac 或 Linux 输入 `npm run check`）。窗口里出现「检查通过」之后，再把 `VERSION` 和 `package.json` 的版本改成同一个更大的数字（例如 `0.3.1` 改成 `0.3.2`），运行 `node scripts/write-update-manifest.js`，把 `VERSION`、`package.json` 和 `update-manifest.json` 一起交到 `main`。试用的人下次启动就会换成这一版。检查没通过就先不要发，避免别人一更新就对不上。

试用的人如果更新之后觉得不对，也可以双击 `check.bat`。通过就还能演戏；没通过就把窗口里的字发给维护的人。

## 试用的人：网络受限时

公开仓库不需要令牌。启动时先直连 GitHub；连不上再按这个顺序自动试公开镜像：

1. `https://gh-proxy.com/`
2. `https://ghfast.top/`
3. `https://gh.llkk.cc/`

镜像地址只拼在公开的 `https://github.com/...` 文件链接前面。令牌不会发给这些网站。

直连和镜像都不通时，再用下面两种方式之一，让这台电脑直接读仓库。

**用 GitHub 官方命令行（装过 `gh` 的话）：**

1. 打开终端，输入 `gh auth login`，按提示登录。
2. 登录的账号必须已经接受上面的仓库邀请。
3. 以后双击 `start.bat` 即可。

**用一只读仓库的令牌：**

1. 打开 GitHub → Settings → Developer settings → Personal access tokens。
2. 做一只只给 `LeeRolling/Playstage---` 的令牌，权限只要 **Contents: Read**。
3. 在剧戏台文件夹里新建文本文件 `data/github-token.txt`，把令牌单独放一行。不要加引号，不要把这个文件发给别人。
4. 更新不会覆盖这个文件。

也可以把令牌放在环境变量 `PLAYSTAGE_GITHUB_TOKEN` 里，效果一样。

## 暂时不更新

在 `data/` 里新建一个空文件，名字叫 `skip-update.txt`。下次启动会跳过检查，直接演戏。想恢复自动更新，删掉这个文件。

环境变量 `PLAYSTAGE_SKIP_UPDATE=1` 也是跳过。
