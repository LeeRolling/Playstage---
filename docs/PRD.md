## 决策摘要（已锁定，须按此实现）

| 决策项 | 锁定结论 |
|--------|----------|
| 平台 | 最终要 PC + 手机；**第一版 = PC 上本地浏览器 Web 应用**。之后同 WiFi 手机访问；再之后外网回家访问。 |
| 安装形态 | **下载后双击即用**（如常见 WebUI：双击 `xxx.bat` 启动）；不要求用户会命令行。 |
| 架构原则 | **UI 与功能严格分离**：改界面不破坏功能，改功能不牵动界面。 |
| 模型 | **本地优先**（用户在自己电脑上跑推理）；云端 API 为次要选项。手机联网后可调用家里 PC 上的本地模型。**产品不分发模型。** |
| 网络 v1 | **先做局域网 / 同一 WiFi**；户外远程访问放到后续阶段。 |

| 抢话规则 | **需要冷静回合**，避免 AI 互聊不停。玩家发言后，NPC 按**对话链条**接话（如 A 喊饿 → B 提议吃饭 → 商定吃什么 → **结束本轮**）；须抑制角色串话与近乎复制粘贴的雷同回复。 |
| 会话形态 | **场景内多人 → 群聊；仅一人（+玩家）→ 一对一**；随剧情进展可切换（加人/减人即切换形态）。 |
| 内容体系 | **世界书 + 人设卡 + 群聊/一对一**。角色保持人设；世界提供设定。剧情必须可存档（如第 20 回合死亡，第 50 回合不能复活）。人设卡/世界书可导入导出，方便用户之间分享。 |

| 人设卡格式 | **兼容社区常见格式**（如 SillyTavern 风格角色卡等），**不搞仅自有定制格式**；以互通分享为先。 |
| 人设热更新 | **所有人设卡（含 AI 角色与玩家人设）可随时编辑保存**；保存后**立即把当前人设重新加载进进行中的会话**（与世界补丁同一理：很难一次写死）。 |
| 玩家人设 | **玩家也需要人设卡**；可建多张玩家人设；玩家之间可互相导入导出玩家人设卡。 |
| 剧情包分享 | **可导出「剧情包」**给朋友从同一节点继续；包内须含**前文提要**（上一位玩家做了什么、为何推进到当前节点，如「已到森林」）。 |
| 存储 | **全部本地**；打开软件后信息均从本地调用。用文件分享角色卡/世界书/剧情包。**第一版不做付费云存档服务器。** |

| 成人内容与免责 | **必须有免责声明**：剧戏台只提供软件本身，**不提供、不分发 AI 模型**；模型从何处下载由用户自行负责。产品侧**仅建议**前往官方渠道下载官方开源模型。 |
| UI 方向 | 灵感来自 SillyTavern 的能力，但做**原创、友好的深色沉浸式游戏面板**，不是克隆 ST 界面。 |
| 角色立绘 | **人设卡（玩家人设 + NPC）均可添加头像与全身图**；会话演出时用于展示在场角色。 |

## 1. 一句话产品定义

**剧戏台**是一款装在自己电脑上的多角色 AI 文字小说 / 群聊工具：你导入或创建「世界书」和「人设卡」（含头像与全身立绘），在 **Galgame 式**深色沉浸界面里和多个 AI 角色一起演戏（下方半透明对话框，上方展示地点背景与在场人物）；故事会真实存档（死了就是死了）；模型优先跑在你自己电脑上，数据也只存在本地；**项目开源**。

## 2. 目标用户与使用场景

### 2.1 目标用户

- **主用户**：喜欢角色扮演、同人、文字互动小说的玩家；会装软件、会点设置，但**不会写代码**。
- **次用户**：会做/会改人设卡、世界书的创作者，希望把卡发给朋友一起玩。
- **非目标用户（第一版）**：指望「注册账号、云端自动同步、随时随地开玩」的轻量用户（第一版没有云存档服务器）。

### 2.2 典型使用场景

1. **晚间单人演戏**：在 PC 浏览器打开剧戏台，选一个「赛博修仙」世界（已配若干地点图），拉进三个带立绘的角色卡，用「点谁谁回」模式在 Galgame 舞台上推进一章剧情；写到角色死亡时存档，下次打开仍是死亡状态。
2. **和朋友换卡 / 换剧情包**：把人设卡（含玩家人设）或世界书导出成文件发给朋友；也可导出「剧情包」（含当前进度 + 前文提要），朋友从同一节点接着玩（不经过任何官方云端）。
3. **家用局域网**：电脑在跑本地模型；手机连家里 WiFi，用浏览器打开剧戏台页面继续聊（后续阶段；第一版先保证 PC 本地可用）。
4. **本地模型 + 偶尔云 API**：平时用本机 Ollama；出差没带大模型时，临时改成 OpenAI 兼容云 API（密钥自己填，数据仍主要在本地）。

### 2.3 日常怎么用（非技术说明）

1. 下载后**双击启动脚本**（如 `xxx.bat`）打开剧戏台，浏览器自动或按提示打开本地页面。
2. 走完**新手引导**：检测本机配置（如显存）→ 按建议选/装本地模型（需人工完成；可去 https://www.canirun.ai/models 自查匹配）→ 阅读免责声明。
3. 在「模型设置」里选：本机模型（推荐）或云 API。
4. 导入或新建「世界书」（一本主世界；后续可用「副本补丁」补充设定）。
5. 导入或新建若干「人设卡」（可配头像与全身图），并选一张「玩家人设卡」代表你自己，放进一个「会话」（多人则群聊，仅一人则一对一）。
6. 为世界书补充地点/情景图（城市、店铺等）；选发言模式，开始打字互动——界面为 Galgame 式：下方对话框，上方随地点切换背景并显示在场立绘；缺图时鼓励当场添加。随时存档 / 读档；中途改人设保存后立即生效。
7. 想分享：导出人设卡 / 玩家人设 / 世界书文件；或导出「剧情包」（含前文提要）给朋友从同一节点继续。
8. 首次接本地模型时，按向导**自行**安装/启动本机推理软件（产品不内置模型；需人工完成的步骤会标明）。

## 3. 第一版目标与非目标

### 3.1 第一版目标（MVP 要做到）

- **双击即用**：提供下载包与启动脚本（如 `xxx.bat`），非技术用户无需命令行即可打开 PC 本地 Web 界面。
- PC 浏览器可完整使用：世界书（一本 + 副本补丁 + 地点图）、人设卡（含玩家人设、头像与全身图）、群聊/一对一、Galgame 演出舞台、存档与剧情包、导入导出、模型配置、三种发言模式切换。
- **新手引导**：首次启动含硬件检测（显存等）、按配置推荐本地文本模型、指向 https://www.canirun.ai/models 自查、4GB 底线说明与无匹配时的安抚文案；**不分发模型**。
- 人设卡导入导出**兼容社区常见格式**（如 SillyTavern 风格），不以自有格式为唯一通道；人设保存后**立即热加载**进当前会话。
- 数据全部落在本机目录；关闭软件再打开，剧情状态不丢。
- 能接本地推理（如 Ollama）以及 OpenAI 兼容云 API（二选一或可切换）；**不内置、不分发模型**。
- 首次使用流程中含**免责声明**（软件 ≠ 模型；模型下载自负；建议官方开源渠道）。
- UI 为深色沉浸式原创界面，并采用 **Galgame 演出布局**（下方半透明对话框；上方地点背景 + 在场角色立绘）；信息层级清楚，适合长时间阅读聊天；**UI 与功能分层**，互不牵连改动。
- 人设卡支持**头像 + 全身图**（玩家与 NPC）；世界书支持**地点/情景自定义图**，对话进入地点时背景自动切换；无图时鼓励当场添加。
- **开源**：仓库最终公开源码（可先私有后公开，或直接公开，见「开源与仓库策略」）。
- 文档与界面用语对非技术用户友好（少术语，必要时有一句话解释；人工步骤需标明）。

### 3.2 第一版明确不做（非目标）

| 不做项 | 原因 |
|--------|------|
| 租服务器做云存档 / 账号同步 | 成本与隐私边界；v1 坚持本地优先 |
| 外网穿透 / 户外远程回家访问 | 复杂度高，放到后续阶段 |
| 照搬 SillyTavern 的界面与交互 | 只借鉴能力概念，做原创友好 UI |
| 手机独立 App（原生） | v1 是 PC 本地 Web；手机同 WiFi 访问属后续 |
| 付费订阅、应用内购 | 第一版无商业化服务器 |
| 语音、实时语音通话、实时视频形象 | 超出文字小说 / 群聊范围；**静态立绘 + 地点背景**属于 Galgame UI，不在此禁列 |
| 自动爬取他人角色卡网站 | 版权与合规风险；只做用户主动导入导出 |
| 保证「模型永远听话 / 永不 OOC」 | 依赖用户所选模型能力，产品只提供结构与约束工具 |
| 内置或代下 AI 模型权重 | 只提供软件；模型由用户自备；界面可链到官方开源下载建议与 canirun.ai 自查 |
| 同一会话挂多本完整世界书 | 只允许一本世界书 + 副本补丁补充 |
| 抢话模式下无限制互聊 | 必须有冷静回合与对话链结束条件 |

## 4. 核心概念

### 4.1 世界书（World Book）

- **是什么**：一本书式的设定库——地理、势力、时代规则、专有名词解释、剧情禁忌等。
- **干什么**：在聊天时按规则把相关条目「提醒」给模型，让故事待在同一个世界里，而不是每个角色各说各话。
- **和角色的关系**：世界管「舞台与规则」；角色管「谁在台上、怎么说话」。
- **会话绑定（已锁定）**：**一个会话只挂一本世界书**，不可同时挂多本完整世界书。
- **副本补丁（已锁定）**：允许在主世界书之上增加「副本补丁」，用于后续持续补充、细化设定（承认前期很难一次写完）。补丁是对同一世界的增量，不是第二本并行世界书。
- **可分享**：世界书与补丁均可导出为文件，导入到别人的剧戏台。
- **场景与地点图（已锁定）**：可为世界中的**地点 / 情景**绑定自定义图片（城市、店铺、通用居民/村民立绘等）。当会话剧情进入某地点（例如「ABC 城市」「喵喵咖啡馆」）时，**演出背景自动切换**为该地点图。若当前地点尚无用户设定图片，界面**鼓励用户当场自行添加**（不阻断聊天，以引导为主）。

### 4.2 人设卡（Character Card）

- **是什么**：一个角色的身份说明书：名字、外貌摘要、性格、说话风格、背景、与玩家关系、禁忌等。
- **干什么**：保证多角色群聊时，每个角色「像自己」，而不是糊成同一个 AI 腔。
- **格式策略（已锁定）**：**兼容社区常见角色卡格式**（如 SillyTavern 风格等），便于生态互通；**不采用「仅剧戏台自有、互不兼容」的定制路线**。内部存储可有规范化表示，但对用户可见的导入导出必须以社区互通为首要目标。
- **随时编辑与热加载（已锁定）**：**所有人设卡（含 AI 角色卡与玩家人设卡）均可随时更改、编辑、保存**。保存完毕后，**立即把当前人设重新加载进进行中的会话**（无需重启会话才能生效）。理由与世界补丁相同：很难一次性把性格写得足够具体。
- **立绘资源（已锁定）**：**玩家人设卡与 NPC 人设卡均可添加头像与全身图片**（本地图片文件）。头像用于列表/气泡识别；全身图用于 Galgame 主舞台展示在场角色。缺图时仍可纯文字游玩，并鼓励补图。
- **可分享**：导入导出文件，方便用户 A 的卡进入用户 B 的世界（文件分享，不经官方云）；导出包宜尽量带上用户已绑定的本地立绘引用（实现阶段定打包规则）。
- **与剧情包的关系**：单独导入人设卡只带「人设」（及可选立绘），不自动带别人的存档；若要接着同一条剧情，需单独导入「剧情包」（见 4.6）。

### 4.2.1 玩家人设卡（已锁定）

- **玩家也需要人设卡**：会话中的「我」用一张玩家人设描述（称呼、性格、背景、说话习惯等），而不是只有一个空昵称。
- **可建多张**：用户可保存多张玩家人设，开会话时选用其中一张。
- **可交流**：玩家人设卡与角色人设卡一样支持导入导出，玩家之间可互相分享「我」的设定。

### 4.3 会话（Session：群聊或一对一）

- **是什么**：选定一本世界书（可加副本补丁）+ 若干人设卡 + 玩家本人之后，开出的一场「戏」。
- **形态（已锁定）**：
  - 场景内有**多名**参与角色（相对玩家）→ **群聊**；
  - 仅有**一名**参与角色 → **一对一**聊天，不应呈现多人群聊壳子；
  - 随剧情进展加人/减人时，界面与发言逻辑可在群聊与一对一之间切换。
- **包含**：消息历史、当前发言模式、关联世界（一本 + 可选补丁）、参与角色、剧情状态快照引用。
- **一句话**：会话 = 这一次开玩的房间；人多人少决定是群戏还是对戏。

### 4.4 剧情状态 / 死亡（必须可持久化）

- **原则**：重要事实一旦发生并写入状态，就必须能在之后回合被遵守。
- **硬例子**：角色在第 20 回合死亡 → 存档后，第 50 回合不得「假装没死」复活（除非世界规则允许复活且玩家/剧情明确触发）。
- **实现含义（给开发的产品语言）**：除聊天记录外，要有「事实状态表」或等价机制（存活、**当前地点**、持有物、关系标志等），生成回复时必须参考；读档 = 消息 + 状态一起恢复；**当前地点**同时驱动 Galgame 背景切换。
- **用户可见**：状态可在面板查看（至少：谁活着、当前地点、关键标记）；高级编辑可放后续版本。

### 4.5 发言模式（设置中可切换）

| 模式 | 用户怎么理解 | 行为要点 |
|------|----------------|----------|
| **严格轮流** | 大家排队说话 | 按设定顺序或固定规则轮流；一轮一人，减少抢戏 |
| **抢话 / 打断** | 像真人群聊，谁急谁插嘴 | 见下方「抢话细则」；须有冷静回合，禁止无休止互聊 |
| **点谁谁回** | 我点名谁，谁才说话 | 玩家点选目标角色；未点名的角色默认不主动长篇抢戏 |

三种模式均为第一版必做，可在设置（或会话内快捷入口）切换；切换时需提示「是否影响当前未完成的一轮」。

#### 抢话 / 打断细则（已锁定）

- **冷静回合**：一轮插话结束后进入冷静，避免 AI 角色之间一直对话下去、刷屏不停。
- **对话链条**：玩家发言后，后续 NPC 台词应承接**本轮第一个发言角色**所打开的话题，形成自然接话链，而不是各自跑题。示例：A 说「我今天好饿，想吃东西」→ B 说「那我们去吃点别的」→ ……直到**决定吃什么**，本轮即可结束，不必无限延续。
- **抑制串话与雷同**：须避免角色之间串话（说成别人的口吻/立场），以及近乎复制粘贴、内容高度雷同的回复。

### 4.6 剧情包（存档分享，已锁定）

- **是什么**：可导出的一整包进度，供朋友在自己的剧戏台里**从同一节点继续玩**。
- **必须包含**：
  - 当前会话进度（消息历史与剧情状态，含死亡/地点等）；
  - 关联的世界书与参与人设（或明确引用，保证接收方可还原舞台）；
  - **前文提要**：用人话概括「上一位玩家做了什么、为何推进到当前节点」（例如：已进入森林，因为追查失踪商队）。
- **接收方体验**：导入后起始点与导出方一致（如已在森林）；可先阅读前文提要再开聊。
- **与单卡分享区别**：换卡 = 换演员；剧情包 = 连同舞台进度一起交接。

### 4.7 模型责任边界与免责声明（已锁定）

- 剧戏台**只提供软件**，**不提供、不分发 AI 模型**。
- 用户自行决定从何处获取与运行模型；下载与合规责任在用户。
- 产品内**仅建议**前往**官方渠道**下载**官方开源模型**（具体链接在实现阶段写入帮助页；不引导非官方来源）。
- **必须有免责声明**（首次使用或模型设置入口可见）：明确上述边界；成人/敏感内容由用户所选模型与自觉决定，软件侧不做模型内容审查承诺。
- 安装本机推理软件、下载模型权重等步骤属于**需人工完成**项，界面与文档需标明，不伪装为「点一下全自动装好模型」。
- 硬件与模型匹配自查入口：https://www.canirun.ai/models （见 §4.8 新手引导）。

### 4.8 新手引导 / 教程（已锁定）

- **必须有**：面向「完全不懂配置」的用户，首次启动走引导，不可假设用户会自己找模型。
- **第一步：检测本机配置**（至少包括显存等可检测项；检测失败时用人话说明并给出手动选择路径）。
- **按配置推荐**：例如检测到约 8GB 显存，则推荐适合 8GB 的合规本地文本推理模型方向（推荐文案与具体模型列表在实现阶段维护；产品仍**不代下模型**）。
- **底线说明**：即便仅约 **4GB** 显存，也说明存在相对应的轻量化模型可选，但**体验不会很好**；给予预期管理，而非直接拒绝使用。
- **自查链接**：引导用户可前往 https://www.canirun.ai/models 自行查询显卡适合哪些模型。
- **无匹配时**：若查不到合适匹配，**温和安抚**即可（不嘲讽、不强制购买硬件）；可提示改用云 API（用户自备）或继续用轻量本地模型。
- 引导结束前须覆盖免责声明确认（与 §4.7 一致）。

### 4.9 对话演出 UI：Galgame 模式（已锁定）

- **布局**：采用视觉小说 / Galgame 常见表现——**对话框在屏幕下方，半透明**；对话框以外（上方/中景）展示当场剧情的**地点背景**与**出场人物立绘**。
- **当场内容**：例如对话发生在 B 市「喵喵咖啡馆」，人物有主人公、角色 B、角色 C → 屏幕应出现对应**咖啡馆背景**，以及主人公与 B、C 的设定图（全身/立绘优先；无全身图时可降级为头像或剪影占位）。
- **随剧情切换**：地点变化 → 背景自动切换；角色进出场 → 舞台立绘同步增减。
- **缺图引导**：当前地点（或角色）没有用户设定图片时，**鼓励用户现场自行添加**，不强制中断对话；可用轻量提示条/按钮完成。
- **与深色沉浸一致**：整体仍为深色沉浸游戏面板气质；Galgame 布局是主聊天舞台的默认演出形态，不是另做一套无关皮肤。
- **非目标澄清**：此处为**静态立绘 + 背景图**，不等于实时视频形象或语音通话（后者仍属第一版非目标）。

## 5. 功能清单（按模块）

### 5.1 世界书

- 新建 / 编辑 / 删除世界书。
- 条目管理：标题、正文、关键词（或触发条件的简化版）、启用/禁用。
- 会话绑定：**一个会话只关联一本世界书**。
- **副本补丁**：可对已绑定世界书增加/编辑/启停补丁条目，用于持续补充设定；补丁随世界书一并导入导出（或作为附属文件，实现阶段定格式，不另开「多世界书并行」能力）。
- 导入 / 导出世界书文件（用于分享）。
- **地点 / 情景图库**：为城市、店铺等地点或情景绑定自定义背景图；可为通用 NPC/村民等绑定通用立绘；会话进入该地点时主舞台背景自动切换；无图时鼓励当场添加。
- （MVP 简化）触发逻辑可用「关键词命中则注入」；复杂权重与递归注入可放完善阶段。

### 5.2 人设卡（含玩家人设）

- 新建 / 编辑 / 删除人设卡（NPC 角色）。
- 新建 / 编辑 / 删除**玩家人设卡**；支持多张，会话内选用其一。
- 字段至少包括：名称、简介、人格/说话风格、示例对话（可选）、**头像（可选本地图片）**、**全身图 / 立绘（可选本地图片）**；玩家人设与 NPC 均支持。
- **随时编辑**：会话进行中亦可打开编辑；**保存后立即热加载**当前人设到进行中的会话（AI 卡与玩家人设均适用）。
- 导入 / 导出：兼容社区常见格式（如 SillyTavern 风格）；玩家人设同样可导入导出、互相分享。
- 在会话中添加 / 移除角色；同一角色可出现在不同会话（状态按会话隔离）；加人/减人可触发群聊 ↔ 一对一形态切换（见 4.3）。

### 5.3 会话聊天（群聊 / 一对一）

- 创建会话：选**一本**世界书（可加副本补丁）、选参与角色、命名会话。
- **形态**：多名参与角色时为群聊 UI；仅一名时为一对一 UI；剧情中加人/减人可切换。
- 发送玩家消息；按当前发言模式生成角色回复。
- **抢话模式**：执行冷静回合、对话链条收束、抑制串话与雷同回复（见 4.5）。
- **Galgame 主舞台**：下方半透明对话框承载对白；上方展示当前地点背景 + 在场角色全身/立绘（主人公 + NPC）；地点/人员变化时舞台同步更新；缺图时鼓励当场添加。
- 对话框内仍区分说话者（名字/头像色）；群聊与一对一共用该演出壳，仅参与人数与发言调度不同。
- 重新生成某一条 AI 回复（可选但强烈建议 MVP 有）。
- 手动插入「旁白 / 系统句」（可选；若工期紧可放到完善阶段）。
- 上下文过长时的摘要或裁剪策略（MVP 至少有「保留最近 N 条 + 状态表」的说明与实现；精细策略完善阶段优化）。

### 5.4 存档与剧情包

- 手动存档 / 读档 / 另存为多个档位。
- 存档内容必须包含：消息历史 + 剧情状态（含死亡等）+ 会话配置快照。
- 自动存档（可选开关；默认建议开启「退出前自动存」或定时）。
- **剧情包导出 / 导入（MVP 必做）**：导出给朋友从同一节点继续；包内必须含**前文提要**（上一位玩家行为与到达当前节点的原因摘要）。
- **不做**：官方云端存档同步。

### 5.5 导入导出

- 人设卡 / 玩家人设卡文件导入导出（**社区常见格式兼容为 MVP 要求**，非完善阶段再补）。
- 世界书文件导入导出。
- **剧情包**导出/导入（含前文提要；见 4.6），兼作本机备份或拷到另一台电脑。
- 格式需文档化（给创作者），优先易读、可版本升级；内部可规范化，但对用户以社区互通格式为主通道。

### 5.6 模型配置

- **本地优先**：配置本机推理地址（例如 Ollama 或任意 OpenAI 兼容本地服务）、模型名、温度等常用参数。
- **云 API 次要**：填写 API Base、Key、模型名；Key 只存在本地，不明文上传到剧戏台官方（官方本来也无云存档）。
- **不内置模型**：帮助文案写明用户需自行安装推理软件与下载模型；**需人工完成**的步骤在向导中逐步标出。
- **按硬件推荐**：结合新手引导的显存检测结果给出推荐方向；并提供 https://www.canirun.ai/models 自查入口；4GB 底线说明与无匹配安抚文案见 §4.8。
- **免责声明入口**：模型设置页可见；强调只提供软件、建议官方开源下载渠道。
- 连接测试按钮（成功/失败人话提示）。
- 会话可选用「跟随全局」或「本会话单独模型」（完善阶段可增强；MVP 全局一套即可）。

### 5.7 设置

- 发言模式全局默认 + 会话内覆盖（含抢话冷静/链条相关说明入口）。
- 主题：深色沉浸为默认（第一版可不做多主题）。
- 字体大小、气泡密度（阅读舒适度）。
- 数据目录位置显示（让用户知道文件在哪，便于备份）。
- 语言：界面简体中文。
- **关于 / 免责声明**：软件边界、模型自备、官方开源下载建议；首次启动需确认已读。
- **重新打开新手引导**（可选入口，方便老用户复查推荐）。

### 5.8 安装与启动

- 提供下载包；用户解压后**双击启动脚本**（如 Windows 上 `xxx.bat`，类常见 WebUI 体验）即可启动本地服务并打开界面。
- 不要求用户先会用终端或手动装一长串开发工具才能「看见窗口」（具体打包技术选型不影响本条产品要求）。

### 5.9 架构约束（产品级）

- **UI 与功能严格分离**：界面层变更不得破坏核心功能（会话、存档、模型调用、卡格式等）；功能层变更不得强迫重做整套 UI。验收时以此为拆分与回归原则。

## 6. 界面与交互原则（深色沉浸 + Galgame 演出）

### 6.1 视觉

- 深色背景、低刺眼对比、偏「游戏面板 / 视觉小说剧场」而非办公软件。
- 角色用稳定的名字色、头像与**全身立绘**区分；系统/旁白用另一种弱样式。
- 少霓虹堆砌、少无意义动效；强调可读性与长时间阅读不累。
- 地点背景与立绘以用户自定义图为主；无图时用克制占位，并给出「添加图片」引导，而非空白吓人。

### 6.2 布局（建议信息架构）

- **左（可折叠）**：会话列表 / 世界与角色库入口。
- **中 — 主舞台（Galgame）**：
  - **上/中区域**：当前地点**背景图** + 当场出场人物的**全身/立绘**（主人公与在场 NPC）；
  - **下方**：**半透明对话框**（对白、说话者名、常用操作）；
  - 地点变更 → 背景自动切换；角色进出 → 立绘增减。
- **右或抽屉**：当前世界摘要、角色状态（存活等）、发言模式快捷切换、**快速补地点图/立绘**入口。
- **顶或设置页**：模型、导入导出、数据目录、开源关于页。

### 6.3 交互原则

- 所有危险操作（删卡、删档、清空会话）二次确认。
- 专业词第一次出现用人话解释（如「世界书 = 故事的设定库」）。
- 失败提示写原因和下一步（如「连不上本地模型 → 请确认本机推理软件已打开」）。
- 当前地点或角色缺图时：**鼓励当场添加**（轻提示 + 一键打开添加），不强制中断剧情。
- 不模仿 SillyTavern 的密集高级面板做第一眼体验；高级项可收进「高级设置」。
- 一对一与群聊共用同一功能内核与同一 Galgame 舞台壳，仅呈现人数与发言调度不同（UI/功能分离的具体体现）。

## 7. 技术方向建议（给后续开发，少术语）

> 本节给开发看「为什么」；产品验收以功能与体验为准，不绑定某一品牌工具。

| 方向 | 建议 | 为什么 |
|------|------|--------|
| 形态 | **本地 Web 应用**（浏览器打开，服务跑在用户 PC 上） | 方便以后同 WiFi 手机访问同一页面；一套界面兼顾 PC，少做两套原生 App |
| 安装启动 | **下载包 + 双击脚本**（如 `xxx.bat`） | 对齐常见 WebUI 习惯；非技术用户零命令行 |
| 架构 | **UI 与功能分层** | 改皮不伤骨、改骨不翻皮；利于并行迭代与验收 |
| 数据 | **本机数据目录**（世界书、人设卡、存档、设置均文件化） | 符合「全本地、可备份、可文件分享」；用户拷贝文件夹即可搬家 |
| 本地模型 | 对接 **Ollama** 或任意 **OpenAI 兼容**本地接口 | 用户社区常见、配置相对简单；不必绑死一家 |
| 云模型 | 同一套「OpenAI 兼容」客户端，换地址和 Key | 本地与云切换成本低，实现一套对话链路 |
| 网络演进 | v1 本机回环 / 局域网；后续再做安全的远程访问 | 先满足「家里同一 WiFi」；外网涉及安全与穿透，单独阶段做 |
| 前端气质 | 现代 Web UI，深色主题 + **Galgame 主舞台组件**（背景层 / 立绘层 / 半透明对话框层） | 做出原创沉浸感，而不是复刻 ST |
| 资源 | 本地图片目录管理头像、全身图、地点背景 | 与全本地存储一致；导入导出可打包引用 |
| 开源 | 源码开源；许可证建仓时确认 | 先私有后公开或直接公开，见「开源与仓库策略」 |
| 不引入 | v1 不租云数据库、不做必须登录的账号体系；不分发模型权重 | 与产品原则一致 |

**给非技术读者的翻译**：软件主要装在你家电脑上；浏览器只是「遥控器」；故事和角色文件像文档一样躺在硬盘里；AI 可以是家里电脑算的，也可以是你自己填的网上 API。

## 8. 分阶段路线图

### 阶段 A — MVP（第一版可玩）

- 下载包 + **双击启动**；PC 本地 Web 可用；UI/功能分层。
- **新手引导**（显存检测、模型推荐方向、canirun.ai 自查、4GB 说明、免责声明）；不分发模型。
- 世界书（一本 + 副本补丁 + **地点/情景图**）、人设卡（含多张玩家人设、**头像 + 全身图**、保存即热加载）、群聊/一对一、三种发言模式（含抢话冷静与对话链）、本地存档、**剧情包（含前文提要）**、卡/世界/玩家人设导入导出。
- **社区常见人设卡格式兼容**（MVP 必做）。
- 本地模型 + 云 API 配置；人工安装模型步骤标明。
- **Galgame 式深色沉浸 UI**（下方半透明对话框；上方背景 + 在场立绘；地点切换自动换背景；缺图鼓励当场添加）。
- 剧情状态（至少支持死亡、**当前地点**等关键事实持久化）。
- **开源准备**：选定许可证文案与 README；仓库按「先私有后公开」或「直接公开」之一执行（见开源策略）。

### 阶段 B — 完善

- 更好的世界书触发与长对话摘要；补丁管理体验增强；场景图库与通用村民立绘管理体验增强。
- 存档管理体验（多档位、备注、剧情包提要可编辑增强）；剧情包打包立绘/背景资源规则完善。
- 更多社区格式变体与世界书格式兼容加深（含社区卡内嵌立绘互通）。
- 状态面板可视化与有限手动修订；立绘进出场过渡更顺滑（仍非视频）。
- 性能与稳定性；新手引导文案与推荐列表迭代。
- 若阶段 A 仍为私有仓，本阶段完成**开源公开**与贡献指南。

### 阶段 C — 手机 / 同 WiFi

- 同一局域网下，手机浏览器访问家里 PC 上的剧戏台。
- 触控优化（点选角色、模式切换）。
- 手机仍依赖家里 PC 提供页面与（通常）本地推理。

### 阶段 D — 外网远程回家（更晚）

- 安全的远程访问方案（具体技术另议：需考虑密码、加密、风险提示）。
- **仍不默认等于**「我们租服务器帮你云存档」；远程的是访问你家那台机器。
- 若未来要做可选云备份，单独立项，不混进 D 的必做项。

## 10. 验收标准（第一版怎样算做成）

以下全部满足，视为 MVP 可演示、可给朋友试用：

1. **安装与打开**：在一台普通 Windows PC 上（macOS 若同期提供则同标准），用户解压下载包后**双击启动脚本**（如 `xxx.bat`）即可打开使用；无需开发者手动改代码或敲命令行。
2. **新手引导**：首次启动走引导——尽量检测显存等配置 → 给出对应推荐方向（含约 8GB 示例）→ 对约 4GB 给出「有轻量模型但体验有限」说明 → 提供 https://www.canirun.ai/models 自查 → 无匹配时温和安抚；全程**不代下、不分发模型**。
3. **模型**：能配置并成功调用至少一种本地 OpenAI 兼容接口；也能配置一种云 API；失败时有人话报错。产品**不内置模型**；帮助中标明需人工安装推理软件/下载模型，并建议官方开源渠道。
4. **免责声明**：首次启动（或进入模型设置前）可阅读并确认免责声明：只提供软件、不提供模型、模型与内容责任在用户。
5. **建世界与角色**：可创建世界书条目与**副本补丁**；一个会话仅绑定一本世界书；可创建至少 2 张 NPC 人设卡 + 至少 1 张玩家人设卡；多人进会话为群聊、仅一人为一对一；玩家人设可另存多张并切换。
6. **人设热加载**：会话进行中编辑并保存某人设（NPC 或玩家）后，后续生成已按新设定生效，无需重启会话。
7. **三种发言模式**：设置中切换严格轮流 / 抢话 / 点谁谁回，且行为可感知差异。抢话模式下可见：会进入冷静/收束、按话题链条接话、不明显串话或雷同刷屏。
8. **死亡持久化**：在会话中将角色标记为死亡（或剧情导致写入状态）→ 存档 → 读档 → 继续聊天，模型侧与状态面板均不得无故复活。
9. **社区格式导入导出**：至少一种社区常见人设卡格式（SillyTavern 风格等，具体规格见开放问题 9）可导入并用于会话；导出文件可被另一干净数据目录的剧戏台导入；玩家人设与世界书（含补丁）亦可文件分享。
10. **剧情包**：可导出剧情包并在另一实例导入后从同一节点继续；包内含可读的**前文提要**（说明上一位玩家做了什么、为何到达当前节点）。
11. **本地数据**：用户能在数据目录看到自己的文件并完成备份拷贝；无官方云存档依赖。
12. **UI — Galgame 演出**：深色沉浸主界面完成；主聊天为下方**半透明对话框** + 上方**地点背景与在场立绘**；进入已配置地点时背景自动切换；缺地点图时出现鼓励添加的引导且不阻断对话。主要任务（开聊、存档、导出剧情包、导入卡、改模型、补图）不超过三层点击可到达；UI/功能分层可被目录或说明体现。
13. **立绘与场景图**：可为玩家人设与 NPC 分别设置头像与全身图并在舞台展示；可为世界书地点绑定背景图并随剧情切换；无图可玩、有引导补图。
14. **开源**：仓库具备开源许可证与说明（或已确认「先私有后公开」的时间点与检查清单）；源码意图对社区公开，与「用户数据本地私有」不冲突。
15. **非目标守住**：无官方云存档、无外网穿透、无 ST 克隆式主界面、不内置/代发模型权重、无多本完整世界书并行绑定、无实时视频形象冒充立绘。
16. **非技术可用性**：按本文「日常怎么用」，未读过代码的试用者能在 30 分钟内完成「走引导 → 导入卡（含可选立绘）→ 选玩家人设 → 开聊（看到 Galgame 舞台）→ 存档 → 导出剧情包或再读档」（本地模型需事先按向导人工装好的前提下）。

## 附录 B — 与 SillyTavern 的关系（澄清）

- **借鉴**：多角色、世界书、角色卡、本地模型生态等「能力地图」。
- **不借鉴**：界面照搬、菜单结构复制、项目名或品牌暗示。
- **产品立场**：剧戏台是面向非技术用户的原创本地优先产品；ST 是能力与卡格式生态的灵感/互通对象之一，**不是**要兼容的皮肤或品牌目标。
- **格式互通 ≠ UI 抄袭**：人设卡等文件格式可兼容；界面与交互必须原创。
